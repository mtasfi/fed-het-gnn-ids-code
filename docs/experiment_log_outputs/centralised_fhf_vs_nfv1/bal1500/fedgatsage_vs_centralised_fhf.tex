{\Large\bfseries FedGATSage vs.\ centralised XGBoost/RF on NF-ToN-IoT and \mbox{NF-ToN-IoT-FHF}}\\[2pt]
FedHetFormer-IDS experiment log \S11p and \S11r \quad·\quad 27 September 2026

\textbf{Setup.} The same 1500-rows-per-label sets were used for every run (seed 42; mitm 1,295, ransomware 142 in NF; scanning 1,460, dos 283, ransomware 142 in FHF). All 10 labels, no payload.
FedGATSage: \texttt{asfi50/Fed\_GNN} branch \texttt{v2}, 5 clients, 15 rounds; test $\approx$10\,\% (1,344 / 1,239 flows).
Centralised: branch \texttt{centralised} scripts, per-flow features only (IPs and source port dropped), \texttt{-{}-samples-per-class 1500 -{}-min-raw-count 1}; test 20\,\% split by flow vector (2,851 / 3,248 flows).
FHF = NF-ToN-IoT v1 with \texttt{Attack}/\texttt{Label} taken from matched ToN-IoT PCAP/Zeek flows (Kaggle \texttt{mtasfi/nftoniot-fhf}).

\textbf{Reading.}
\begin{itemize}\setlength{\itemsep}{1pt}
\item With equal settings, the centralised flow-only models clearly beat FedGATSage: macro-F1 $\approx$0.71 against 0.45--0.47.
\item L7 (injection, password, xss) is the weakest group in every run. The only L7 F1 above 0.56 is FedGATSage on FHF password (0.75), and the same model gets xss almost entirely wrong on both datasets.
\item FHF helps the centralised models on password (+0.18--0.21 F1) and xss (+0.09--0.11), but overall macro-F1 by only $\approx$0.01.
\item One seed, and 140--330 test flows per L7 class. The FedGATSage and centralised test splits differ, so differences of 1--2 points are noise. The gap of 0.71 against 0.47 is not.
\end{itemize}
